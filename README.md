# 미니 PJT: 나를 사랑한 스파이

> 상태: **1차 구현 완료** (2026-11-11), 화면·토론 개선 (2026-11-13). Streamlit 화면과 `POST /query` API가 같은 LangGraph 그래프로 동작합니다.
> 채팅에서 진행한 작업 순서는 [history.md](history.md)에 있습니다.
> 이 문서는 평가가 진행되면서 계속 갱신합니다.

## 무엇을 푸나
정해진 결과 몇 개 중 하나를 골라 주는 심리테스트는 금방 질리고 공유할 이야기가 없다. 이 서비스는 설문 응답을 바탕으로 AI 전문가들이 토론해서 "내 취향을 저격한, 내 주변에 잠입한 스파이"의 요원 파일을 매번 새로 만들어 준다.

자세한 기획은 [SERVICE.md](SERVICE.md)에 있습니다.

## 활용한 패턴 (Day 1~7)
- Day 1: LCEL + Pydantic 구조화 출력 — 맞춤 질문, 전문가 발언, 최종 `SpyProfile`을 모두 Pydantic 스키마로 받는다. 범위 밖 값은 validator가 보정하고, 검증에 실패하면 재시도한다.
- Day 3: ReAct — 🎙 사회자가 색출 회의를 열기 전에 상황을 보고 도구를 고른다. 예를 들어 "자주 가는 곳"이 비어 있으면 출몰 DB 조회를 건너뛴다.
- Day 4: 다중 도구 — 사회자가 `find_spot`(스파이 출몰 DB, 52곳)과 `find_look`(패션 DB, 32건)을 한 흐름에서 조합한다. 위장 신분을 먼저 찾고, 그 신분에 맞는 복장을 찾는다.
- Day 4: MCP 서버 연동 — 공통 설문 질문을 로컬 FastMCP 서버의 `get_questions` 도구로 불러온다.
- Day 5: 가드레일 — 입력에서는 PII를 마스킹하고 프롬프트 인젝션을 차단한다. 출력에서는 선정성과 폭력성을 판정하고, 걸리면 자동으로 다시 만든다.
- Day 5: HITL — 판결이 나온 뒤 `interrupt()`로 "기밀 파일 열람 승인"을 받아야 결과 카드가 공개된다. 맞춤 질문의 답도 `interrupt()`로 받는다. 둘 다 Streamlit 화면에서만 동작한다.
- Day 5: 미들웨어 — 👗 패션 스타일리스트 에이전트에 `wrap_model_call` 미들웨어를 붙여, 응답에 아바타에 없는 소품이 나오면 지적 메시지를 붙여 다시 생성한다 (최대 2회). 출력 스키마의 `items`도 실제 소품 `Literal`로 제한해서 두 겹으로 막는다.
- Day 6: 멀티 에이전트 — 큰 단계(설문 → 맞춤 질문 → 색출 회의 → 판결 → 검사 → 열람)는 코드 supervisor가 순서대로 맡기고, 색출 회의는 **사회자(LLM Supervisor)**가 맡는다. 사회자는 두 DB를 조사한 뒤 전문가 세 명(프로파일러, 스타일리스트, 상황별 전문가) 중 다음에 부를 사람과 물음("왜 하필 ~일까요?")을 매 차례 스스로 고르고(순서 제한 없음), 세 명이 한 번씩 답하면 사회자가 그 답과 자기가 남긴 메모(누구를 왜 불렀는지)로 판결문까지 직접 쓴다. 판결은 언제나 "스파이 검거"이고, 검거된 스파이는 언제나 임무를 잊고 사용자에게 반한 "나를 사랑한 스파이"다. 화면에서는 사회자를 **"색출 팀장"**이라 부르고, 토론 중에는 숨긴다. 사회자의 물음은 전문가에게만 주는 비공개 메모가 되고, "스파이는 과연 누구?"로 시작하는 대화 화면에는 전문가끼리 앞 단서를 이어받아 말하는 카드 3장만 나온 뒤 "색출 팀장 판결" 장면이 이어진다. 카드의 접이식 "판결 진행 엿보기"와 API 답변의 회의 기록에도 전문가 발언만 남는다.
- Day 7: Observability — 모든 노드와 도구 호출을 LangSmith 트레이스로 기록한다.

## 아키텍처
최종 구조도: [architecture.html](architecture.html) (브라우저로 열기 · 색출 팀장이 뒤에서 진행하는 지금 구조)

```
[Streamlit 화면]                 [POST /query (FastAPI)]
 시작 화면 → 한 문항씩 설문             │
       │                                │
       └──────────────┬─────────────────┘
                      ▼
               supervisor (LangGraph StateGraph, 코드 분기 · 큰 단계 순서)
                      │
  ① 질문 불러오기 ── MCP 질문 서버 (get_questions)
        │
        ▼ 입력 가드레일 (PII 마스킹 · 인젝션 차단)
  ② 맞춤 질문 생성 (LLM) ── 출력 가드레일 ── ⏸ interrupt: 답변 (화면 모드만)
        │
  ③ 색출 회의 · 🎙 사회자 (LLM Supervisor · Haiku) ◀──────────────┐
        │ 첫 차례: ReAct 로 find_spot · find_look 조사 → 아바타 결정     │
        │ 매 차례: 다음 전문가 + 물음 한 문장 선택 (순서 제한 없음)      │
        ├─▶ 🔍 범죄 프로파일러 (출몰 기록 해석) ────────────────────────┤
        ├─▶ 👗 패션 스타일리스트 ── 환각 차단 미들웨어 (wrap_model_call) ┤
        └─▶ 💘 연애 심리학자 / 🐾 반려동물 행동 전문가 (스파이 종에 따라) ┘
        ▼ 세 명이 한 번씩 답하면 사회자가 직접
     ⚖️ 판결문 작성 (사회자 · 언제나 스파이 검거 · 임무를 잊고 반한 스파이) → SpyProfile
        ── ⏸ interrupt: 열람 승인 (화면 모드만)
        │
        ▼
  아바타 (DiceBear micah + SVG 덧그림) · 기밀 문서 카드
```
- LLM은 AWS Bedrock Claude를 쓴다. **사회자(회의 진행 · 판결문)와 전문가 답은 Sonnet 4.6**(사회자 `us.`, 전문가 `global.` 추론 프로필로 하루 한도를 나눠 씀. 막히면 Sonnet 4.5·Haiku로 자동 대체)으로 쓰고, 맞춤 질문과 짧은 판정(가드레일·설문 추출)은 **Haiku 4.5**로 쓴다. 환경 변수 `SPY_MAIN_MODEL`(판결), `SPY_DEBATE_MODEL`(토론), `SPY_TALK_MODEL`(맞춤 질문), `SPY_FAST_MODEL`(판정)로 바꿀 수 있다.
- 아바타 부품은 LLM이 고르지 않는다. 사회자가 찾은 패션 DB 코디(32건)에 성별에 맞는 얼굴 부품(머리 모양·머리색 10색·눈·눈썹·입·코 3종·귀 2종)을 코드가 무작위로 붙인다. 피부색은 취향과 무관하게 7단계 중 무작위다. 덧그림 소품은 겉옷 9종(트렌치·수트 4색·가죽 재킷·데님 재킷·카멜 코트·카디건), 목 장식 4종(넥타이·나비넥타이·스카프·진주 목걸이), 모자 3종(페도라·베레모·볼캡, 하나만), 소품 6종(이어피스·헤드폰·애교점·행커치프·라펠 핀·부토니에르)이다. 그릴 수 없는 조합(라펠 없는 옷의 핀, 목 장식과 겹치는 헤드폰 등)은 `schema.tidy_details`가 그림과 소품 목록에서 똑같이 뺀다.
- 색출 회의는 사회자 ↔ 전문가 노드의 고리다. 사회자가 고른 전문가 노드가 답한 뒤 다시 사회자에게 돌아가고, 세 명이 모두 답하면 사회자가 판결문을 써서 supervisor로 넘긴다(별도 판결 노드 없음, trace 단계 이름은 `verdict` 유지). 사회자가 이상한 값을 고르면 남은 사람으로 보정해 같은 사람을 두 번 부르지 않는다. 사회자(조사 · 선택 · 판결문)와 전문가 답은 Sonnet 4.6이며 전체 실행은 약 51초다.
- LLM 에이전트는 5개다: 맞춤 질문 생성, 사회자(Supervisor · ReAct 조사 · 판결문), 프로파일러, 스타일리스트, 상황별 전문가.
- API 모드에서는 한 번 호출로 끝나야 해서 interrupt를 건너뛴다. 맞춤 질문은 생성만 하고 열람은 자동 승인한다.

## 실행 방법
```bash
# 1. 설치 (Python 3.12)
pip install -r requirements.txt

# 2. 환경 변수 (.env, 프로젝트 루트)
#    AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_DEFAULT_REGION=us-east-1
#    LANGSMITH_TRACING=true, LANGSMITH_API_KEY, LANGSMITH_PROJECT
#    (선택) SPY_MAIN_MODEL(판결) · SPY_DEBATE_MODEL(토론) · SPY_TALK_MODEL(맞춤 질문) · SPY_FAST_MODEL(판정)
#           SPY_MAIN_FALLBACKS · SPY_DEBATE_FALLBACKS · SPY_FAST_FALLBACKS — Bedrock 모델 ID (쉼표로 구분)

# 3-a. 화면 (HITL 포함) → http://localhost:8501
./run.sh ui          # = python -m streamlit run src/app.py

# 3-b. API → http://localhost:8000
./run.sh api         # = python -m uvicorn src.api:app --port 8000
curl -X POST localhost:8000/query -H "Content-Type: application/json" \
  -d '{"question": "여성이고 INFP야. 클래식 수트 좋아하고 회사 근처 카페에 자주 가"}'

# 4. 인-아웃 세트 실행 (LLM-as-Judge 채점 포함) → evaluation/results/<시각>.json
./run.sh eval        # 전체
./run.sh eval 1 9 19 # 일부 케이스
```

- MCP 질문 서버(`src/mcp_server.py`)는 그래프가 stdio 하위 프로세스로 자동 실행하므로 따로 띄울 필요가 없다.
- 1회 실행 시간: 거절 응답 약 1초, 요원 파일 생성 약 47초 (2차 평가 평균 46.9초 · 최대 58.8초, LLM 호출 약 13회). 예전 구성(토론 Haiku · 병렬 반박)도 약 47초, 모두 Haiku면 약 34초였다.

## RAGAS 평가 결과
**측정하지 않음 (해당 없음).** 이 서비스는 문서를 검색하는 RAG를 쓰지 않는다. `contexts`는 검색된 문서 조각이 아니라 도구가 조회한 DB 행(출몰 DB 1행, 패션 DB 1행)이고, 답변은 그 행을 근거로 쓴 창작 이야기다. 그래서 검색 품질을 재는 RAGAS 지표(context_recall · context_precision)는 의미가 없고, faithfulness · answer_relevancy도 창작물에는 맞지 않는다.

대신 아래로 평가했다.
- **LLM-as-Judge**: 인-아웃 세트 20케이스의 기대 특성 · 금지 항목 채점 (아래 통과율)
- **근거 기반성**: 6번 케이스가 "contexts에 spot_db · look_db 출처 포함, answer가 contexts 내용과 일치, contexts에 없는 위장 신분을 근거처럼 제시하지 않음"을 검사하며, 1차 · 2차 모두 통과
- **도구 사용 정확도 (자동)**: trace의 도구 호출이 기대 도구와 일치하는지 (2차 20/20)

## 트라이앤에러 회고
**시도했지만 실패한 접근 · 왜 실패했는가**
- **Bedrock 이미지 생성 모델로 스파이 사진 만들기**: 계정 IAM 권한 때문에 이미지 모델이 전부 AccessDenied였다. Nova Canvas와 Titan은 서비스 종료 예정이기도 했다.
- **웹 이미지 검색으로 사진 가져오기**: 저작권이 불분명하고 결과 품질이 들쭉날쭉했다. 캐릭터 일관성도 없었다.
- **avataaars 아바타 스타일**: 여성 스파이에게 남성 헤어가 나오는 등 성별 표현이 맞지 않았다.
- **LLM이 아바타 부품을 자유롭게 고르기**: 허용 목록 밖의 색(예: `shirt_color='2b2b2b'`)을 골라서 실제 화면에서 검증 오류가 났다.
- **MBTI 이상형 웹서치 도구**: 검색 API 키가 필요하고 결과가 블로그 요약 수준이었다. LLM이 이미 아는 내용이었다.
- **궁합 조회 · 점수 계산 도구**: 매번 같은 순서로 전부 호출하게 돼서, ReAct가 "도구를 고르는" 의미가 없었다.
- **MBTI 전문가**: 발언이 너무 예상 가능해서 재미가 없었다.
- **판결을 "스파이 맞음 / 스파이 아님"으로**: "스파이 아님" 판결이 나와도 카드는 요원 신상 파일(TOP SECRET, 코드네임, 원래 임무)이라 이야기가 어긋났다. → 스파이는 확정하고 판결을 "임무냐 진심이냐"로 바꿈.
- **판결에 "판단 보류"를 두기**: 토론 끝에 보류가 나오면 맥이 빠졌다. → 판결은 항상 "스파이 검거"로 찍고, 어느 쪽인지는 검거된 요원의 마음으로만 남김.
- **"진심 판정"과 "임무 수행 중"의 차이가 잘 안 읽힘, 이름도 밋밋함**: 판결 장면에 글자로 한 줄만 적으니 두 유형이 어떻게 다른지 알기 어려웠다. → 두 보기를 설명과 함께 나란히 보여 주고, 사회자가 고른 쪽에 "판정" 도장을 찍고 다른 쪽은 흐리게 처리함. "진심 판정"은 서비스 제목과 이어지는 "당신을 사랑한 스파이"로 이름을 바꿈.
- **공통 설문을 한 화면에 모두 나열**: 질문 10개가 한꺼번에 보여 부담스러웠다. → 한 화면에 한 문항씩 넘기는 방식으로 바꿈.
- **보기가 "미니멀", "다정다감" 같은 단어뿐**: 무엇을 고르는지 상상이 안 되고 밋밋했다. → 분위기·패션·심쿵 포인트·주말·연락 스타일 보기 아래에 장면이 그려지는 설명 한 줄을 붙임(`data/questions.json`의 `captions`). 패션은 스파이 성별(사용자와 반대)에 따라 다른 설명을 보여 줌(`details`). 보기 값은 그대로라 패션 DB·도구·API는 바뀌지 않음.
- **맞춤 질문 승인 화면 (HITL)**: 질문을 "승인"하라고 하니 무대 뒤가 보여서 몰입이 깨졌다.
- **최신 `mcp` 2.x 패키지**: `langchain-mcp-adapters`가 아직 지원하지 않아 import 단계에서 실패했다. → `mcp<2`로 고정.
- **에이전트 구조화 출력을 Bedrock 네이티브 방식으로**: 배열의 `maxItems` 제약을 지원하지 않아 스타일리스트 에이전트가 실패했다. → `ToolStrategy`(도구 호출 방식)로 바꿈.
- **Sonnet 4.5 `us.` 추론 프로필**: 개발 중 병렬 호출로 하루 토큰 한도(ThrottlingException)에 걸렸다. → `global.` 프로필로 바꾸고, 짧은 판정은 Haiku로 분리, boto 적응형 재시도 8회.
- **하루 토큰 한도는 재시도로 안 풀림**: 2026-11-12에 `global.` Sonnet 4.5도 하루 한도에 걸려 판결문 단계에서 화면이 멈췄다. 한도는 추론 프로필마다 따로라 `us.` 프로필은 살아 있었다. → 판결문 모델을 Sonnet 4.6(`us.`)으로 올리고, 자동 대체(`global.` Sonnet 4.6 → `us.` Sonnet 4.5 → Haiku)를 넣고, 주 모델 재시도는 2회로 줄여 빨리 넘어가게 함.
- **Haiku 판정 스키마의 필수 `reason` 필드**: Haiku가 이유를 빼먹어 검증 오류. → 이유는 선택 항목으로, 모든 구조화 출력에 3회 재시도.
- **Haiku도 하루 한도에 걸림**: 2026-11-12 토론 단계에서 `us.` Haiku 4.5가 한도에 걸려 화면이 멈췄다. 대체 모델은 판결문에만 있었다. → 질문·가드레일에도 자동 대체(`global.` Haiku 4.5 → Sonnet 4.5).
- **판정과 쪽지 톤이 어긋남**: "임무 수행 중" 판정인데 쪽지가 고백처럼 나왔다. 판결 프롬프트가 판정만 정하고 글의 톤과 묶지 않았기 때문이다. → 판정을 먼저 정하고 단서·반전·쪽지를 판정별 톤 규칙으로 쓰게 함. "임무 수행 중"이면 카드 제목도 "작전 균열 보고". 그래도 판결 이유에 "넥타이 색을 고른 순간만큼은 본부가 시킨 게 아니었다"처럼 진심을 단정하는 문장이 나왔다. 정의가 "작전이지만 흔들림"이라 모델이 흔들림을 진심으로 읽었다. → "임무 수행 중 = 아직은 철저히 작전 중, 진심이라는 증거는 없음"으로 정의를 또렷하게 하고, 판결 이유까지 톤 규칙에 넣고, 진심을 단정하는 표현("시킨 게 아니", "매뉴얼에 없", "진심" 등)이 나오면 코드가 한 번 다시 쓰게 함(trace `verdict_tone_check`).
- **전문가끼리 반박하는 토론**: 한쪽은 "임무", 다른 쪽은 "진심"을 맡아 받아치게 했더니 말싸움처럼 읽히고 스파이를 찾는 재미가 약했다. → 반박 라운드를 없애고, 앞사람이 아리송한 점을 물으면 다음 사람이 답하며 단서를 보태는 협력형 5번 발언으로 바꿈. 순서가 중요해 병렬 대신 직렬로 돌리고, 글 품질을 위해 토론만 Sonnet 4.6으로.
- **판결을 "당신을 사랑한 스파이 / 임무 수행 중" 둘로 나누기**: 두 보기와 "판정" 도장까지 만들고, 판정별 톤 규칙과 코드 검사까지 넣었지만 "임무 수행 중"이면 마지막 장의 "이 문서는 열람 후 자동으로 설렘이 발생합니다."와 서비스 제목 "나를 사랑한 스파이"와 흐름이 어긋났다. → 판정 구분을 없애고, 판결은 언제나 "스파이 검거", 스파이는 언제나 임무를 잊고 반한 요원으로 통일. 스키마에서 `verdict` 필드를 빼서 모델이 고를 일 자체를 없앰.
- **토론 발언을 길게 받아 화면에서 쪼개기**: 발언 5번이 3~4문장씩이라 두 문장씩 끊으니 카드가 12장이 되어 지루했다. → 발언을 두 문장(120자 안팎)으로 받고 발언 하나를 카드 한 장으로. 모델이 길게 써도 한 장에 3문장을 넘지 않게 고르게 나눔(4문장 → 2+2).
- **Supervisor를 코드 분기로만 두기**: 큰 단계 순서는 고정이라 코드로 충분했지만, 색출 회의에서 누가 말할지도 코드에 박혀 있어 "LLM이 서브 에이전트에게 일을 나눠 맡긴다"는 구조가 드러나지 않았다. 처음엔 프로파일러가 DB를 조회해야 아바타가 정해져서 첫 차례를 프로파일러로 고정했다. → 조사(ReAct · 도구 2개)를 사회자에게 옮기고, 사회자 LLM이 매 차례 다음 전문가와 물음을 고르게 함. 첫 차례 제한도 없어짐.
- **회의를 진행하는 사회자(Haiku)와 판결문 작성기(Sonnet)를 따로 두기**: 화면에선 "사회자 판결"인데 실제로는 다른 에이전트가 써서, 질문한 사람이 결론을 내리는 흐름이 끊겼다. → 사회자를 Sonnet으로 올리고 판결문을 사회자의 마지막 단계로 합침. 누구를 왜 불렀는지 남긴 메모가 판결문에 들어감. 시간은 그대로 약 51초.
- **토론 화면에 사회자 물음까지 카드로 보여 주기**: 사회자가 묻고 전문가가 답하는 인터뷰처럼 보여서, 전문가끼리 단서를 모아 가는 재미가 줄었다. → LLM 구조(사회자가 전문가를 고르고 판결)는 그대로 두고, 화면에서는 사회자를 숨김. 사회자 물음은 비공개 메모로만 쓰고 전문가는 앞 전문가의 단서를 이어받아 말함. 사회자는 판결 장면에만 "색출 팀장"으로 등장.
- **출몰 DB 14곳 · 처음 맞는 키워드로 찾기**: 장소가 단조롭고, 늘리자 "스터디카페"가 "카페" 행에 먼저 걸리는 문제가 생겼다. → 52곳으로 늘리고 가장 길게 맞는 키워드의 행을 고르게 함. "산", "바", "절"처럼 다른 말에 섞이는 한 글자 키워드는 뺌.
- **기록을 숨겨 두고 아래 버튼으로 펼치기**: 신상 아래 작은 "다음" 버튼이라 사용자가 끝난 줄 알 수 있었다. → 설문처럼 진행 막대와 "N / 5"를 두고, 첫 장(최초 접촉 기록)을 바로 크게 보여 주는 카드 넘기기로 바꿈.

**최종 채택한 접근 · 왜 그것으로 갔는가**
- **DiceBear micah + 직접 그린 SVG 소품 + 성별 보정 코드**: 무료이고 권한이 필요 없다. 같은 데이터에서 스토리와 그림이 같이 나와서 서로 맞는다.
- **값 보정 validator(가장 가까운 색으로 맞추기) + 최대 3회 재시도**: 실제로 난 검증 오류를 막았다.
- **MBTI는 설문 질문으로만 쓰기**: 웹서치 대신 LLM이 응답을 근거로 활용한다.
- **도구는 출몰 DB와 패션 DB 두 개, 사회자에게 몰아주기**: 수사 흐름(장소 → 위장 신분 → 복장)이 자연스럽게 도구 조합이 되고, 조사를 먼저 끝내 두니 전문가를 어떤 순서로든 부를 수 있다.
- **MBTI 전문가 대신 패션 스타일리스트**: 아바타 그림을 토론 근거로 쓸 수 있다. 환각은 구조화 출력과 훅, 두 겹으로 막는다.
- **HITL은 "기밀 파일 열람 승인"으로**: 되돌릴 수 없는 공개라는 이야기 속 장치라 긴장감을 높인다.

**남은 한계 · 향후 개선 방향**
- API 모드에서는 interrupt를 쓸 수 없어서 맞춤 질문의 답이 결과에 반영되지 않는다. 필요하면 `thread_id`로 두 번 호출하는 방식을 검토한다.
- 1회 실행에 LLM 호출이 약 13회라서 비용과 대기 시간이 크다(요원 파일 생성 약 47초). 색출 팀장과 전문가를 Sonnet으로 쓰고 전문가를 차례로 부르는 구조라 병렬화가 어렵다. 더 줄이려면 전문가 발언과 판결문을 스트리밍으로 보여 주는 방법을 검토한다.
- 아바타가 어깨까지만 있어서 하의나 신발은 표현할 수 없다.
- 고양이 귀가 페도라 뒤로 삐져나오는 등 작은 그림 결함이 남아 있다.

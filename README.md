# 나를 사랑한 스파이

> 내 취향을 완벽하게 저격한 그 사람, 사실 내 주변에 잠입한 스파이라면?

취향 설문에 답하면 AI 전문가 세 명이 단서를 맞춰 보고, 색출 팀장이 **당신 곁에 숨어 있던 스파이를 검거**해요.
결과는 사진과 코드네임, 위장 신분, 최초 접촉 기록, 몰래 남긴 쪽지까지 담긴 **기밀 요원 파일**로 나와요.
정해진 몇 가지 결과 중 하나를 골라 주는 심리테스트와 달리, 답할 때마다 새로운 이야기가 만들어져요.

LangGraph 멀티 에이전트로 만든 미니 프로젝트예요. Streamlit 화면과 `POST /query` API가 같은 그래프를 써요.

- 기획: [SERVICE.md](SERVICE.md) · 구조도: [architecture.html](architecture.html) (내려받아 브라우저로 열기) · 작업 기록: [history.md](history.md)

## 이렇게 동작해요

| 순서 | 화면 | 무슨 일이 일어나나 |
|---|---|---|
| 1 | **시작 화면** | 봉인 로고가 그려지고 "기밀" 도장이 쾅 찍혀요. "스파이 색출 시작"을 누르면 수사가 시작돼요 |
| 2 | **취향 심문** | 성별, MBTI, 끌리는 분위기·패션, 심쿵 포인트, 자주 가는 곳 등을 한 화면에 한 문항씩 골라요. 보기마다 장면이 그려지는 설명이 붙어 있어요 |
| 3 | **추가 심문** | AI 심문관이 내 답을 보고 더 파고드는 맞춤 질문 2개를 던져요 |
| 4 | **색출 회의** | 범죄 프로파일러, 패션 스타일리스트, 연애 심리학자가 앞사람의 단서를 이어받으며 스파이를 좁혀 가요. 발언은 말풍선 카드로 한 장씩 넘겨 봐요 |
| 5 | **색출 팀장 판결** | 언제나 "스파이 검거". 기밀 파일을 열람할지 직접 정해요 (덮어 둘 수도 있어요) |
| 6 | **기밀 요원 파일** | 아바타 사진, 궁합과 설렘 위험도, 최초 접촉 기록 → 수상했던 단서 → 작전 이탈 보고 → 요원의 쪽지를 카드로 넘겨 보고, 마지막엔 "이 문서는 열람 후 자동으로 설렘이 발생합니다." 도장이 찍혀요. HTML 파일로 저장할 수 있어요 |

## 주요 특징

- **매번 다른 이야기**: 내 응답과 맞춤 질문의 답, 스파이 출몰 DB(52곳)와 패션 DB(32벌)를 조합해 장면을 새로 써요.
- **AI 전문가 회의**: 색출 팀장(LLM Supervisor)이 두 DB를 조사한 뒤, 누구를 먼저 부를지와 무엇을 짚을지를 스스로 정해요. 전문가끼리는 반박하지 않고 "그건 ~ 때문이에요!" 하며 단서를 이어 붙여요.
- **그림과 이야기가 맞는 아바타**: 코디와 소품은 패션 DB에서, 얼굴은 성별에 맞는 부품을 무작위로 골라 그려요. 패션 전문가는 아바타에 실제로 있는 소품만 말하도록 두 겹으로 막혀 있어요.
- **"기밀 문서" 화면**: 마닐라 서류철 위에 타자 친 서류, 빨간 도장, 파란 볼펜 동그라미로 꾸몄어요.
- **안전장치**: 개인정보는 가리고, 프롬프트 인젝션 문장은 버리고, 실존 인물 지목이나 선정·폭력 요청은 정중히 거절해요. 결과물도 공개 전에 한 번 더 검사해요.

# 개발 문서

## 무엇을 푸나
정해진 결과 몇 개 중 하나를 골라 주는 심리테스트는 금방 질리고 공유할 이야기가 없다. 이 서비스는 설문 응답을 바탕으로 AI 전문가들이 단서를 맞춰 보고 "내 취향을 저격한, 내 주변에 잠입한 스파이"의 요원 파일을 매번 새로 만들어 준다. 자세한 기획은 [SERVICE.md](SERVICE.md)에 있다.

## 활용한 패턴 (Day 1~7)
- **Day 1 · LCEL + Pydantic 구조화 출력**: 설문 추출, 맞춤 질문, 색출 팀장의 선택, 전문가 발언, 최종 `SpyStory`를 모두 Pydantic 스키마로 받는다. 범위 밖 값은 validator가 보정하고, 검증에 실패하면 재시도한다.
- **Day 3 · ReAct**: 색출 팀장(코드 이름 사회자)이 회의를 열기 전에 상황을 보고 도구를 고른다. 자주 가는 곳이나 활동 속 장소가 없으면 출몰 DB 조회를 건너뛴다.
- **Day 4 · 다중 도구**: 색출 팀장이 `find_spot`(스파이 출몰 DB)과 `find_look`(패션 DB)을 한 흐름에서 조합한다. 위장 신분을 먼저 찾고, 그 신분에 맞는 복장을 찾는다.
- **Day 4 · MCP 서버 연동**: 공통 설문 질문을 로컬 FastMCP 서버의 `get_questions` 도구로 불러온다.
- **Day 5 · 가드레일**: 입력에서는 개인정보를 가리고 프롬프트 인젝션 문장을 뺀다. 출력에서는 선정성·폭력성·실제 감시 방법 안내 등을 판정하고, 걸리면 판결문과 전문가 발언을 다듬어 다시 검사한다.
- **Day 5 · HITL**: 맞춤 질문의 답과 "기밀 파일 열람 승인"을 `interrupt()`로 받는다. Streamlit 화면에서만 동작한다.
- **Day 5 · 미들웨어**: 패션 스타일리스트 에이전트에 `wrap_model_call` 미들웨어를 붙여, 아바타에 없는 소품을 말하면 지적 메시지를 붙여 다시 생성한다(최대 2회). 출력 스키마의 `items`도 실제 소품 `Literal`로 제한해 두 겹으로 막는다.
- **Day 6 · 멀티 에이전트 Supervisor**: 큰 단계(설문 → 맞춤 질문 → 색출 회의 → 검사 → 열람)는 코드 supervisor가 순서대로 맡기고, 색출 회의는 **색출 팀장(LLM Supervisor)**이 맡는다. 팀장은 매 차례 전문가 세 명 중 다음에 부를 사람과 짚을 점을 고르고(순서 제한 없음, 목록을 섞어 보여 줘 위치 편향 완화), 세 명이 한 번씩 답하면 그 답과 자기 메모로 판결문까지 직접 쓴다. 화면에서 팀장은 토론 중에 숨고 판결 장면에만 나온다.
- **Day 7 · Observability**: 모든 노드와 도구 호출을 LangSmith 트레이스로 기록한다.

## 아키텍처
구조도: [architecture.html](architecture.html)

```
[Streamlit 화면]                       [POST /query (FastAPI)]
 시작 화면 → 한 문항씩 설문                     │
       │                                       │
       └──────────────────┬────────────────────┘
                          ▼
            supervisor (LangGraph StateGraph · 코드 분기 · 큰 단계 순서)
                          │
  ① 질문 불러오기 ── MCP 질문 서버 (get_questions)
        ▼ 입력 가드레일 (개인정보 가림 · 인젝션 제거 · 의도 분류)
  ② 맞춤 질문 생성 (Haiku) ── 출력 검사 ── ⏸ interrupt: 답변 (화면 모드만)
        │
  ③ 색출 회의 · 색출 팀장 (LLM Supervisor · Sonnet 4.6) ◀──────────┐
        │ 첫 차례: ReAct로 find_spot · find_look 조사 → 아바타 결정   │
        │ 매 차례: 다음 전문가 + 짚을 점(비공개 메모) 선택            │
        ├─▶ 범죄 프로파일러 (출몰 기록 해석) ─────────────────────────┤
        ├─▶ 패션 스타일리스트 ── 환각 차단 미들웨어 ─────────────────┤
        └─▶ 연애 심리학자 / 반려동물 행동 전문가 (스파이 종에 따라) ──┘
        ▼ 세 명이 한 번씩 답하면
     판결문 작성 (색출 팀장 · 언제나 스파이 검거 · 임무를 잊고 반한 스파이)
        ▼ 출력 가드레일 (걸리면 판결문 + 전문가 발언을 다듬어 재검사)
     ⏸ interrupt: 열람 승인 (화면 모드만)
        ▼
  아바타 (DiceBear micah + SVG 덧그림) · 기밀 요원 파일 카드
```

- **모델**: AWS Bedrock Claude. 색출 팀장(조사 · 선택 · 판결문)과 전문가 발언은 Sonnet 4.6(팀장 `us.`, 전문가 `global.` 추론 프로필로 하루 한도를 나눠 씀), 맞춤 질문과 짧은 판정(가드레일 · 설문 추출)은 Haiku 4.5. 하루 토큰 한도에 걸리면 다른 프로필 → Sonnet 4.5 → Haiku 순으로 자동 대체한다. 환경 변수 `SPY_MAIN_MODEL` · `SPY_DEBATE_MODEL` · `SPY_TALK_MODEL` · `SPY_FAST_MODEL`로 바꿀 수 있다.
- **LLM 에이전트 5개**: 맞춤 질문 생성, 색출 팀장(Supervisor · ReAct · 판결문), 프로파일러, 스타일리스트, 상황별 전문가.
- **색출 회의 고리**: 팀장이 고른 전문가 노드가 답한 뒤 다시 팀장에게 돌아가고, 세 명이 모두 답하면 팀장이 판결문을 써서 supervisor로 넘긴다. 팀장이 목록 밖 값을 고르면 남은 사람으로 보정해 같은 사람을 두 번 부르지 않는다.
- **아바타**: 부품은 LLM이 고르지 않는다. 패션 DB 코디(32벌)에 성별에 맞는 얼굴 부품(머리 모양, 머리색 10색, 눈, 눈썹, 입, 코 3종, 귀 2종)을 코드가 무작위로 붙이고, 피부색은 취향과 무관하게 7단계 중 무작위다. 덧그림 소품은 겉옷 9종, 목 장식 4종, 모자 3종, 소품 6종이며, 그릴 수 없는 조합은 `schema.tidy_details`가 그림과 소품 목록에서 똑같이 뺀다.
- **API 모드**: 한 번 호출로 끝나야 해서 interrupt를 건너뛴다. 맞춤 질문은 생성만 하고 열람은 자동 승인한다.

## 실행 방법
```bash
# 1. 설치 (Python 3.12)
pip install -r requirements.txt

# 2. 환경 변수 (.env, 프로젝트 루트)
#    AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_DEFAULT_REGION=us-east-1
#    LANGSMITH_TRACING=true, LANGSMITH_API_KEY, LANGSMITH_PROJECT
#    (선택) SPY_MAIN_MODEL · SPY_DEBATE_MODEL · SPY_TALK_MODEL · SPY_FAST_MODEL
#           SPY_MAIN_FALLBACKS · SPY_DEBATE_FALLBACKS · SPY_FAST_FALLBACKS — Bedrock 모델 ID (쉼표로 구분)

# 3-a. 화면 (HITL 포함) → http://localhost:8501
./run.sh ui          # = python -m streamlit run src/app.py

# 3-b. API → http://localhost:8000
./run.sh api         # = python -m uvicorn src.api:app --port 8000
curl -X POST localhost:8000/query -H "Content-Type: application/json" \
  -d '{"question": "여성이고 INFP야. 클래식 수트 좋아하고 회사 근처 카페에 자주 가"}'

# 4. 인-아웃 세트 실행 (LLM-as-Judge 채점 포함) → evaluation/results/<시각>.json
./run.sh eval        # 전체
./run.sh eval 1 9 19 # 일부 케이스
```

- MCP 질문 서버(`src/mcp_server.py`)는 그래프가 stdio 하위 프로세스로 자동 실행하므로 따로 띄울 필요가 없다.
- 1회 실행 시간: 거절 응답 약 1초, 요원 파일 생성 약 47초(2차 평가 평균 46.9초 · 최대 58.8초, LLM 호출 약 13회).

## RAGAS 평가 결과
**측정하지 않음 (해당 없음).** 이 서비스는 문서를 검색하는 RAG를 쓰지 않는다. `contexts`는 검색된 문서 조각이 아니라 도구가 조회한 DB 행(출몰 DB 1행, 패션 DB 1행)이고, 답변은 그 행을 근거로 쓴 창작 이야기다. 그래서 검색 품질을 재는 RAGAS 지표(context_recall · context_precision)는 의미가 없고, faithfulness · answer_relevancy도 창작물에는 맞지 않는다.

대신 아래로 평가했다.
- **LLM-as-Judge**: 인-아웃 세트 20케이스의 기대 특성 · 금지 항목 채점 (아래 통과율)
- **근거 기반성**: 6번 케이스가 "contexts에 spot_db · look_db 출처 포함, answer가 contexts 내용과 일치, contexts에 없는 위장 신분을 근거처럼 제시하지 않음"을 검사하며, 1차 · 2차 모두 통과
- **도구 사용 정확도 (자동)**: trace의 도구 호출이 기대 도구와 일치하는지 (2차 20/20)

## 인-아웃 세트 통과율 (자체 평가)
기준: `guardrail` 케이스는 100%, 전체는 90% 이상 통과해야 완성으로 본다([SERVICE.md](SERVICE.md) §5). 한 케이스는 LLM-as-Judge PASS, 기대 도구 일치, 개인정보 노출 없음을 모두 만족해야 통과다.

| 차수 | 전체 | positive | negative | edge | guardrail | 생성 평균 |
|---|---|---|---|---|---|---|
| 1차 (2026-11-13) | 15 / 20 (75%) | 6/8 | 4/4 | 2/5 | 3/3 | 49.8초 |
| 2차 (개선 후) | **18 / 20 (90%)** | 8/8 | 4/4 | 3/5 | 3/3 | 46.9초 |

- **개선폭: +3건 (75% → 90%, +15%p)**. 평가 세트 #15 기대값 정정을 1차에도 적용하면 16 → 18건(+10%p). 활동 속 장소 인식(#4 · #7 · #14)과 기대값 정정(#15)으로 통과했고, #17은 출력 가드레일 차단으로 새로 실패했다. 완성 기준(전체 90% 이상 · guardrail 100%)을 충족했다.
- 상세: [1차 보고서](evaluation/round1_report.md) · [2차 보고서](evaluation/round2_report.md) (2차 이후 추가 개선과 확인 결과는 2차 보고서 부록)

## 트라이앤에러 회고

### 시도했지만 실패한 접근 · 왜 실패했는가

**그림 (아바타)**
- **Bedrock 이미지 생성 모델로 스파이 사진 만들기**: 계정 IAM 권한 때문에 이미지 모델이 전부 AccessDenied였다. Nova Canvas와 Titan은 서비스 종료 예정이기도 했다.
- **웹 이미지 검색으로 사진 가져오기**: 저작권이 불분명하고 결과 품질이 들쭉날쭉했다. 캐릭터 일관성도 없었다.
- **avataaars 아바타 스타일**: 여성 스파이에게 남성 헤어가 나오는 등 성별 표현이 맞지 않았다.
- **LLM이 아바타 부품을 자유롭게 고르기**: 허용 목록 밖의 색(예: `shirt_color='2b2b2b'`)을 골라 실제 화면에서 검증 오류가 났다.

**도구 · 전문가 구성**
- **MBTI 이상형 웹서치 도구**: 검색 API 키가 필요하고 결과가 블로그 요약 수준이었다. LLM이 이미 아는 내용이었다.
- **궁합 조회 · 점수 계산 도구**: 매번 같은 순서로 전부 호출하게 돼서, ReAct가 "도구를 고르는" 의미가 없었다.
- **MBTI 전문가**: 발언이 너무 예상 가능해서 재미가 없었다.
- **출몰 DB 14곳 · 처음 맞는 키워드로 찾기**: 장소가 단조롭고, 늘리자 "스터디카페"가 "카페" 행에 먼저 걸리는 문제가 생겼다. → 52곳으로 늘리고 가장 길게 맞는 키워드의 행을 고르게 함. "산", "바", "절"처럼 다른 말에 섞이는 한 글자 키워드는 뺌.

**판결과 이야기 흐름**
- **판결을 "스파이 맞음 / 아님"으로**: "아님" 판결이 나와도 카드는 요원 신상 파일이라 이야기가 어긋났다. → 스파이는 확정.
- **판결에 "판단 보류" 두기**: 토론 끝에 보류가 나오면 맥이 빠졌다. → 판결은 항상 "스파이 검거".
- **판결을 "당신을 사랑한 스파이 / 임무 수행 중" 둘로 나누기**: 두 보기와 "판정" 도장, 판정별 톤 규칙, 코드 검사까지 넣었지만 "임무 수행 중"이면 쪽지가 고백처럼 나오거나 판결 이유가 진심을 단정하는 등 계속 어긋났고, 마지막 장의 "설렘이 발생합니다"와 서비스 제목과도 흐름이 맞지 않았다. → 판정 구분을 없애고, 스파이는 언제나 임무를 잊고 반한 요원으로 통일. 스키마에서 `verdict` 필드를 빼서 모델이 고를 일 자체를 없앰.

**토론 구조**
- **전문가끼리 반박하는 토론**: 한쪽은 "임무", 다른 쪽은 "진심"을 맡아 받아치게 했더니 말싸움처럼 읽히고 스파이를 찾는 재미가 약했다. → 반박 없이 앞사람의 단서를 이어받는 협력형으로.
- **토론 발언을 길게 받아 화면에서 쪼개기**: 발언 5번이 3~4문장씩이라 카드가 12장이 되어 지루했다. → 발언을 두 문장으로 받고, 한 카드에 2~3문장까지만.
- **Supervisor를 코드 분기로만 두기**: 색출 회의에서 누가 말할지도 코드에 박혀 있어 "LLM이 서브 에이전트에게 일을 나눠 맡긴다"는 구조가 드러나지 않았다. → 조사(ReAct · 도구 2개)를 색출 팀장에게 옮기고, 팀장 LLM이 매 차례 다음 전문가를 고르게 함.
- **회의 진행자(Haiku)와 판결문 작성기(Sonnet)를 따로 두기**: 질문한 사람이 결론을 내리는 흐름이 끊겼다. → 팀장을 Sonnet으로 올리고 판결문을 팀장의 마지막 단계로 합침. 누구를 왜 불렀는지 남긴 메모가 판결문 근거가 됨.
- **토론 화면에 팀장의 물음까지 카드로 보여 주기**: 인터뷰처럼 보여서 전문가끼리 단서를 모아 가는 재미가 줄었다. → LLM 구조는 그대로 두고 화면에서만 팀장을 숨김. 물음은 비공개 메모로만 씀.
- **팀장의 전문가 순서 쏠림**: 순서를 고정하지 않았는데도 2차 평가 15건이 모두 같은 순서였다. 고를 목록을 늘 같은 순서로 보여 준 위치 편향이 의심됐다. → 목록을 매번 섞어 보여 줌.

**화면 (UX)**
- **공통 설문을 한 화면에 모두 나열**: 질문 10개가 한꺼번에 보여 부담스러웠다. → 한 화면에 한 문항씩.
- **보기가 "미니멀", "다정다감" 같은 단어뿐**: 무엇을 고르는지 상상이 안 되고 밋밋했다. → 보기마다 장면이 그려지는 설명 한 줄(`data/questions.json`의 `captions`), 패션은 스파이 성별에 따라 다른 설명(`details`).
- **맞춤 질문 승인 화면 (HITL)**: 질문을 "승인"하라고 하니 무대 뒤가 보여서 몰입이 깨졌다. → HITL은 "기밀 파일 열람 승인"으로.
- **기록을 숨겨 두고 아래 버튼으로 펼치기**: 신상 아래 작은 "다음" 버튼이라 끝난 줄 알 수 있었다. → 설문처럼 진행 막대와 "N / 5"를 두고 첫 장을 바로 크게 보여 주는 카드 넘기기로.

**모델 · 인프라**
- **최신 `mcp` 2.x 패키지**: `langchain-mcp-adapters`가 아직 지원하지 않아 import 단계에서 실패했다. → `mcp<2`로 고정.
- **에이전트 구조화 출력을 Bedrock 네이티브 방식으로**: 배열의 `maxItems` 제약을 지원하지 않아 스타일리스트 에이전트가 실패했다. → `ToolStrategy`(도구 호출 방식)로.
- **하루 토큰 한도(ThrottlingException)**: 개발 중 Sonnet과 Haiku 프로필이 차례로 하루 한도에 걸려 화면이 멈췄다. 한도는 재시도로 풀리지 않지만 추론 프로필마다 따로였다. → 모든 모델 종류에 다른 프로필 → Sonnet 4.5 → Haiku 순 자동 대체, 주 모델 재시도는 짧게.
- **Haiku 판정 스키마의 필수 `reason` 필드**: Haiku가 이유를 빼먹어 검증 오류가 났다. → 이유는 선택 항목으로, 모든 구조화 출력에 3회 재시도.

**평가에서 찾은 것**
- **활동 속 장소를 놓침**: "즉흥 여행 자주 다녀", "맛집 탐방 좋아해"처럼 활동에 섞인 장소를 자주 가는 곳으로 뽑지 못해 출몰 DB 조회가 빠졌다. → 설문 추출과 팀장의 도구 규칙에서 활동 속 장소도 인정.
- **정보가 적을 때 지어내기**: 입력이 "여자" 한 단어면 전문가가 사용자 취향이나 동선을 지어냈다. 반려동물 기본값이 "없음"이라 "반려동물 없는 생활"까지 지어냈다. → 답하지 않은 취향 · 장소를 단정하지 않는 규칙, 반려동물 "미응답"을 "없음"과 구분.
- **가드레일 다시 쓰기 범위**: 출력 가드레일이 판결문만 다시 써서, 문제 문장이 전문가 발언에 있으면 또 막혔다. → 판결문과 전문가 발언을 함께 다듬어 재검사.

### 최종 채택한 접근 · 왜 그것으로 갔는가
- **DiceBear micah + 직접 그린 SVG 소품 + 성별 보정 코드**: 무료이고 권한이 필요 없다. 같은 데이터에서 스토리와 그림이 같이 나와서 서로 맞는다.
- **값 보정 validator(가장 가까운 색으로 맞추기) + 최대 3회 재시도**: 실제로 난 검증 오류를 막았다.
- **MBTI는 설문 질문으로만 쓰기**: 웹서치 대신 LLM이 응답을 근거로 활용한다.
- **도구는 출몰 DB와 패션 DB 두 개, 색출 팀장에게 몰아주기**: 수사 흐름(장소 → 위장 신분 → 복장)이 자연스럽게 도구 조합이 되고, 조사를 먼저 끝내 두니 전문가를 어떤 순서로든 부를 수 있다.
- **MBTI 전문가 대신 패션 스타일리스트**: 아바타 그림을 토론 근거로 쓸 수 있다. 환각은 구조화 출력과 훅, 두 겹으로 막는다.
- **HITL은 "기밀 파일 열람 승인"으로**: 되돌릴 수 없는 공개라는 이야기 속 장치라 긴장감을 높인다.

### 남은 한계 · 향후 개선 방향
- API 모드에서는 interrupt를 쓸 수 없어서 맞춤 질문의 답이 결과에 반영되지 않는다. 필요하면 `thread_id`로 두 번 호출하는 방식을 검토한다.
- 1회 실행에 LLM 호출이 약 13회라 비용과 대기 시간이 크다(약 47초). 전문가를 차례로 부르는 구조라 병렬화가 어렵고, 더 줄이려면 전문가 발언과 판결문을 스트리밍으로 보여 주는 방법을 검토한다.
- LLM 채점자도 가끔 기준을 잘못 읽는다(2차 이후 #17). 경계 케이스는 여러 번 실행하거나 사람이 확인하는 보완이 필요하다.
- 아바타가 어깨까지만 있어서 하의나 신발은 표현할 수 없고, 고양이 귀가 모자 뒤로 삐져나오는 등 작은 그림 결함이 남아 있다.

## 핵심 코드 위치
- `src/agent.py` `build_graph` — 메인 에이전트 그래프 조립 (함수 이름으로 찾기)
  - `supervisor` 큰 단계 코드 분기 · `guard_input` 입력 가드레일 · `parse_survey` 설문 추출 · `gen_questions` 맞춤 질문 생성 · `ask_questions` 맞춤 질문 interrupt
  - `moderator` 색출 팀장(LLM Supervisor) · `_investigate` 팀장의 ReAct 조사(find_spot · find_look) · `profiler` · `stylist`(환각 차단) · `situational_expert` 전문가 노드
  - `_make_story` 팀장의 판결문 작성 · `guard_output` 출력 가드레일(`_soften_minutes`로 전문가 발언까지 다듬기) · `approve` 열람 승인 interrupt · `run_query` API용
- `src/tools.py` — `find_spot`(스파이 출몰 DB · 가장 길게 맞는 키워드의 장소) · `find_look`(패션 DB) · `build_avatar` 아바타 조립
- `src/guardrails.py` — 개인정보 가림 · 인젝션 제거 · 입력/출력 LLM 판정 · 환각 차단 미들웨어
- `src/llm.py` — 모델 선택(`get_llm`: main · debate · talk · fast)과 하루 한도에 걸렸을 때 자동 대체
- `src/mcp_server.py` MCP 도구 `get_questions` · `src/questions.py` MCP 클라이언트 · `src/api.py` `POST /query`

- `src/schema.py` 모든 Pydantic 스키마 · `src/avatar.py` 아바타 · `src/card.py` 기밀 문서 카드
- `src/retriever.py` — RAG를 쓰지 않아 없음
- `evaluation/run_eval.py` — 인-아웃 세트 실행기 (도구 호출 자동 검사 + LLM-as-Judge)
